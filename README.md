# GitStamp

GitStamp is a web application that converts images into pixel patterns for the GitHub contribution graph and automatically provisions a repository in the user's account to keep the artwork centered all year.

- **Web Application**: [https://gitstamp.vercel.app](https://gitstamp.vercel.app)
- **Repository Provisioned**: `username/gitstamp-art` (public repository containing the automated rendering workflow)

---

## Disclaimer

GitStamp is intended strictly for personal visual customization and displaying aesthetic patterns, icons, or logos on your GitHub contribution graph. It is NOT for faking git history, inflating productivity metrics, or falsifying engineering activity. All commits generated by this tool reside exclusively in a dedicated public repository (`gitstamp-art`), are explicitly labeled `art: render`, and include documentation linking back to GitStamp so anyone inspecting your profile can see how the pattern is generated.

---

## How It Works

Users do not need to write scripts or manually create files. The GitStamp web application automates the entire process:

1. **Visit the Web App**: Go to [https://gitstamp.vercel.app](https://gitstamp.vercel.app).
2. **Connect GitHub**: Sign in with GitHub via OAuth PKCE to grant permission to create the public artwork repository.
3. **Upload or Draw**: Upload an image (`PNG`, `JPG`, `SVG`, `WEBP`) or draw pixels directly on the live 53-week GitHub profile preview. GitStamp automatically converts the image into a `7 x N` contribution matrix using Otsu's thresholding.
4. **One-Click Deployment**: Click **Deploy to My GitHub Profile**.
   - GitStamp automatically creates the public repository `gitstamp-art` on your account.
   - It generates and commits `art.json` (your pixel matrix and personal attribution).
   - It installs the automation engine (`scripts/render.mjs`, `.github/workflows/render.yml`, and `README.md`).
   - It triggers the initial render workflow.
5. **Permanent Alignment**: Every Sunday at 01:00 UTC, the workflow runs automatically inside your repository, recalculating dates to keep the artwork centered on your profile graph as the year advances.

   - Calls GitHub REST API to create a public repository named `gitstamp-art`.
   - Commits `art.json`, `scripts/render.mjs`, `.github/workflows/render.yml`, and `README.md`.
   - Dispatches the initial render workflow so the pattern appears on the profile immediately.

## Engine Specifications

### Sunday-Anchored Dynamic Centering
GitHub's contribution graph renders a rolling 53-week window (columns `0` through `52`) ending on the current week's Saturday. Every Sunday at 01:00 UTC, the workflow calculates the UTC date of the current week's Sunday and shifts the artwork to column `startCol = Math.floor((53 - N) / 2)`. This keeps the logo locked in the center of the graph all year.

### Quartile-Exact Color Calibration via GraphQL
The workflow queries GitHub's GraphQL API (`viewer.contributionsCollection.contributionCalendar`) to detect the minimum commit count required for each quartile (`FIRST_QUARTILE` through `FOURTH_QUARTILE`). It injects `Math.max(0, desiredCommits - existingCommitsOnDate)` commits per cell, ensuring consistent shades across high and low activity periods.

### Clean History on an Orphan Branch
Every weekly run rebuilds the render history on a fresh orphan branch (`git checkout --orphan temp-render`) and force-pushes to `main`. This wipes previous weeks' shifted commits cleanly, prevents repository bloat, and resets GitHub's 60-day cron inactivity timer.

### Personal Commit Attribution
Commits are attributed using the owner's official GitHub noreply email address (`{id}+{login}@users.noreply.github.com`) so contributions appear on their personal profile graph rather than being attributed to a bot.
